# 模块 10 游客合并与多设备同步验收清单

## 已实现范围

- 游客档案和各账号档案使用独立 `profileId`，任务、类别、专注记录、积分、成就、计时设置和运行中计时均按当前档案读取。
- 邮箱验证成功后检测游客任务、完整专注记录和积分，并提供“合并游客数据并登录”“不合并、保留游客档案”“取消登录”三项选择。
- 合并采用复制方式，原游客档案不会被自动删除；每个游客实体保存稳定映射，重复导入或网络失败重试不会生成重复副本。
- 账号页允许稍后导入或明确删除游客档案，删除前显示数据概览并二次确认。
- 本地数据库升级到 v4，新增持久化同步变更队列、冲突副本和同步元数据；升级不修改既有业务表数据。
- 账号任务、类别、专注会话、奖励事件和专注设置进入离线变更队列；游客数据不会入队或上传。
- 服务端提供 `POST /v1/sync/push` 和 `GET /v1/sync/pull?cursor=...`，使用账号鉴权、幂等 mutation ID 和服务端递增游标。
- 任务、类别和设置采用版本检查；专注会话和奖励事件采用追加式写入，相同内容去重、不同内容保留冲突。
- 客户端显示待同步数、待处理冲突数、上次同步时间和离线错误；冲突同时保存本机与云端内容，必须选择“采用云端”或“保留本机”。
- 访问令牌接近过期时先轮换刷新令牌，再发起同步。

## 自动与真实环境验收

- 客户端 Debug HAP 使用 DevEco Studio API 26 SDK 构建成功并安装到 API 26 手机模拟器。
- 已在保留模块 9 数据的模拟器上完成数据库 v3 → v4 升级，应用初始化、任务、专注和“我的”页面正常。
- 服务端 NestJS 构建、ESLint 和 Jest 均通过；共 5 个测试套件、15 项测试通过。
- `npm run test:sync-e2e` 已连接真实 PostgreSQL、Redis 和 Mailpit，验证 mutation 重放幂等、游标增量拉取、多设备陈旧版本冲突、追加式会话去重和未授权拒绝。
- 手机模拟器完成真实邮箱登录，识别到 7 个游客任务，显示三项处理选择；选择合并后服务端同步完成，游客原档案仍保留。
- 断开模拟器端口转发后修改专注设置，界面显示 1 项待同步和离线重试说明；恢复连接后再次同步归零。
- 使用第二个设备会话修改同一设置后，手机端显示 1 项冲突并同时提供云端、本机选择；选择保留本机后重新上传成功，待同步与待处理均归零。

## 本地复验步骤

1. 在 `server` 目录启动 PostgreSQL、Redis 和 Mailpit：`docker compose up -d`。
2. 执行 `npm run build`、`npm test`、`npm run lint` 和 `npm run test:sync-e2e`。
3. 启动服务端后，手机模拟器执行 `hdc rport tcp:3000 tcp:3000`。
4. 安装最新 HAP，打开“我的”，完成邮箱验证码登录并检查游客数据三项选择。
5. 合并后检查账号任务和类别，再回到“我的”确认游客概览仍存在、同步队列为 0。
6. 执行 `hdc fport rm tcp:3000 tcp:3000` 模拟断网，修改账号专注设置并点“立即同步”，确认待同步项保留；恢复 `rport` 后重试。
7. 在第二个客户端修改同一任务、类别或设置，再让手机上传旧版本，确认出现冲突卡片且没有静默覆盖。

## 当前限制

- 1.0 按既定决定只完成 API 26 手机模拟器适配；平板最终适配延期到 1.1。
- 当前同步为用户主动触发和登录合并触发；系统后台周期同步可在发布质量阶段结合网络、电量策略补充，但离线队列和失败恢复已完整保留。
- 本地开发地址仍为 `http://127.0.0.1:3000/v1`；发布前必须替换为具备证书、限流和监控的 HTTPS 正式域名。
- 正式邮件供应商、生产数据库、Redis 高可用与备份策略仍需部署环境和正式凭据后完成。

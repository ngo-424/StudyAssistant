# 模块 11：鸿蒙跨设备接续验收记录

## 实现范围

- `EntryAbility` 声明 `continuable: true`，在 `onContinue` 中校验目标应用版本并传递活动计时快照。
- 接续载荷只包含 `ActiveTimerSnapshot`、协议版本、应用账号 ID、设备 ID 和一次性令牌，编码上限为 96 KB，低于官方 `wantParam` 100 KB 限制。
- 目标设备仅在服务端原子认领成功后保存快照；本机已有其他活动计时时不会静默覆盖。
- 源设备在认领处于等待、过期或网络失败时继续计时；确认目标已认领后停止本机通知、代理提醒和实况窗，并禁用本机计时操作。
- 游客不参加跨设备接续；目标设备必须处于相同应用账号。相同华为账号由 HarmonyOS 系统接续能力保证。
- 计时阶段沿用原 `phaseSessionId`。服务端对接续认领建立唯一约束，同步层继续通过会话 UUID 和追加式记录约束阻止重复结算。

## 服务端接口

- `POST /v1/continuation/prepare`：源设备登记哈希后的一次性令牌，令牌有效 2 分钟。
- `POST /v1/continuation/claim`：目标设备原子认领唯一控制权；同一目标重试幂等，其他目标返回冲突。
- `GET /v1/continuation/status?token=...`：源设备确认是否已经转移。

令牌只以 SHA-256 摘要写入 PostgreSQL。账号不匹配、源设备自认领、版本不同、过期和重复目标均有独立错误码。

## 真机验收限制

华为官方说明应用接续不支持模拟器，因此无法在单个手机模拟器中验证系统接续入口及两台设备间的实际迁移。正式真机验收需要：

1. 两台支持 HarmonyOS NEXT 的设备登录同一华为账号，并开启 WLAN、蓝牙和接续功能。
2. 两端安装同一版本、同一正式包名的应用，并登录同一 StudyAssistant 应用账号。
3. 在源设备开始计时后，从目标设备的系统接续入口迁移。
4. 分别复验成功、目标不确认、断网、不同应用账号、不同版本和重复认领。
5. 正式发布前在华为开发者后台完成应用接续能力配置或审批。

官方依据：[App Continuation Overview](https://developer.huawei.com/consumer/en/doc/best-practices/bpta-continue-cast)。
